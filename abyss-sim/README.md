# Abyss: safe multi-ROV net-pen inspection in Isaac Sim

Three ROVs inspect a fish-farm net pen and photograph every section of the net.
A **High-Order Control Barrier Function (HOCBF) safety filter** keeps each ROV away from
obstacles (ropes and hoses hanging through the pen), from the net and from each other, and
water current is accounted for. The filter is ported from the SJTU safe-RL AUV project
(`finrl/cbf.py`).

Outputs:
- inspection photos with labels (which net panel, planted holes and fouling in view)
- safety numbers per ROV (minimum clearance, contact count, how often the filter acts)
- annotated videos:
  - **overview**: a camera orbiting the pen
  - **cutaway**: a cross-section with the near net wall removed
  - **grid**: both side by side
  - each with the three ROV camera feeds along the bottom

```
sim/fishfarm_demo.py          scene + water physics + HOCBF navigation + capture + recording
sim/safe_nav.py               HOCBF filter (numpy), sonar-style rays, policy runner
sim/plan_mode.py              decision-layer plan.json -> waypoints (numpy), for --plan
tests/test_plan_mode.py       laptop tests for plan_mode.py (no Isaac Sim needed)
tools/make_video.py           draws the overlays and encodes the MP4 videos
training/train_fishfarm_nav.py  optional: retrain the PPO navigator (run in the SJTU repo)
scripts/run_cluster.sh        one-command headless run on a GPU server
scripts/slurm_record.sbatch   example SLURM job
scripts/run_local.ps1         local Windows run
```

## Requirements
- **Isaac Sim 5.1** (standalone install or the `nvcr.io/nvidia/isaac-sim:5.1.0` container).
  Nothing else to install: the scene is generated by code and uses only numpy and Pillow, which
  ship with Isaac Sim.
- **An RTX-class GPU** (L40S, A40, RTX 6000 Ada, RTX 4090, ...). A100 and H100 have no RT
  cores, so Isaac Sim cannot render cameras on them.
- ffmpeg, for the videos. If there is no system ffmpeg, `run_cluster.sh` installs
  `imageio-ffmpeg` into Isaac Sim's python.
- ROS 2 is not needed. The scripts clear a sourced ROS 2 Humble environment, because its
  python 3.10 clashes with Isaac Sim's python 3.11.

## Cluster (headless, over SSH)
```bash
git clone <your-repo-url> abyss-sim && cd abyss-sim
ISAACSIM_ROOT=~/isaacsim OUT=~/abyss_out ./scripts/run_cluster.sh
```
This records two runs, `hero` (HOCBF on) and `nocbf` (HOCBF off, for comparison), then renders
the videos:
```
~/abyss_out/rec_hero/abyss_orbit.mp4     overview + ROV feeds
~/abyss_out/rec_hero/abyss_section.mp4   cutaway + ROV feeds
~/abyss_out/rec_hero/abyss_grid.mp4      overview | cutaway + ROV feeds
~/abyss_out/rec_nocbf/...                same with the filter off
~/abyss_out/run_*/nav_summary.json       min clearance / contacts / filter activity per ROV
~/abyss_out/run_*/auv_*/img_*.png        inspection photos (+ captures.jsonl, ground_truth.json)
```
Copy them back to your laptop: `scp "user@cluster:~/abyss_out/rec_*/abyss_*.mp4" .`

Settings (environment variables): `OBST=12 BANDS=2 RES=1920x1080 PATHTRACE=0 RUNS="hero nocbf" EXTRA=--hq`.
- `PATHTRACE=32` gives path-traced frames: much nicer light, slower to render.
- `BANDS=4` or `EXTRA="--hq --full-coverage"` makes a longer, complete inspection.
- `--perception` builds the HOCBF from simulated sonar returns instead of a known map. It
  needs a GPU run to validate.

**SLURM:** `sbatch scripts/slurm_record.sbatch` (edit the partition and account first).

## Acting on the decision layer (`--plan`)
The first run is a sweep: the ROVs cover the whole net and write `captures.jsonl`. The decision
layer (branch `feat/decision-layer`) grades those photos and writes `plan.json`, a ranked list of
net cells with how to look at each one. A plan run flies those targets instead of the sweep:
- each viewpoint is a waypoint `standoff_m` from the net, aimed at the cell centre, so offset
  viewpoints see the same spot from another angle;
- `shots` photos per waypoint;
- `margin_m` is that ROV's HOCBF inflation (one filter per ROV). The margin is raised only as
  far as the ROV already clears, so the barrier never starts out violated;
- a target with two robots gives each robot one viewpoint, and they take turns on the target.
  Side by side they would block each other under the HOCBF;
- every photo carries `target_id`, the plan's `cell`, `viewpoint` and `visit`. That is how the
  decision layer closes the mission;
- `plan_status.json` lists the photos per target and robot, timeouts, and viewpoints a rope blocked;
- `--plan-revisits N` flies the targets N more times, spread through `--plan-coverage N` cells of
  ordinary sweep, so the ranked areas are photographed more often.

The loop, with the decision layer on a laptop:
```bash
# GPU machine: the sweep
RUNS=hero ./scripts/run_cluster.sh
# laptop (decision-layer/): grade, rank and plan
scp -r "user@cluster:~/abyss_out/run_hero" . && npm run stand-in-vision -- run_hero   # until the real detector writes vision.jsonl
npm run cli -- import run_hero && npm run cli -- plan --out plan.json && scp plan.json user@cluster:~/
# GPU machine: act on the plan, with the same OBST / BANDS / EXTRA as the sweep, so the scene matches
RUNS=plan PLAN=~/plan.json PLAN_FLAGS="--plan-revisits 1 --plan-coverage 24" ./scripts/run_cluster.sh
# laptop: close the missions and plan again
scp -r "user@cluster:~/abyss_out/run_plan" . && npm run stand-in-vision -- run_plan && npm run cli -- import run_plan && npm run cli -- plan
```
Laptop tests for the plan logic: `uv run --with numpy --with pytest pytest tests`.
The Isaac side of `--plan` (moving, margins, turns, shots) has not been run on a GPU yet.

## Local (Windows, with a window)
```powershell
cd C:\isaacsim
.\python.bat <repo>\sim\fishfarm_demo.py --safe-nav --obstacles 12 --bands 2 --lite
```
Useful flags:
- `--view section`: watch the cutaway camera.
- `--save-usd scene.usd`: build the scene, save it and quit, then open it with File → Open in
  Isaac Sim.
- `--no-cbf`: turn the filter off.
- `--no-viz`: hide the arrows.

## How the safety filter works
On every physics step (60 Hz), for each ROV:
1. The planner, or a trained PPO policy (`--nav-policy fishfarm_nav.npz`), proposes an
   acceleration `u_nom`. This is the yellow arrow in the videos.
2. Every obstacle within 4 m adds a barrier `h = |p - c|^2 - R^2`, where R is the obstacle
   radius plus 0.6 m (ROV size and safety margin). The net adds an inside-circle barrier.
   Other ROVs are barriers that use their relative velocity.
3. The HOCBF chain (ψ1 = ḣ + α1·h, ψ̇1 + α2·ψ1 ≥ 0, with α1 = 1 and α2 = 2, current-aware)
   turns each barrier into a linear constraint `A·u ≥ b`.
4. A QP (Dykstra projection) returns the safe command closest to `u_nom` that meets every
   constraint and the actuator limits. This is the green arrow, red while the filter is
   changing the command.
5. The ROV follows the same point-mass model the HOCBF was derived on (horizontal water drag
   is cancelled), so the safety guarantee carries over to the simulation.

## Retraining the navigator (optional)
Copy `sim/safe_nav.py` and `training/train_fishfarm_nav.py` into the SJTU_SafeRL_AUV repo, then
run them in its python 3.10 venv:
```bash
python train_fishfarm_nav.py --selftest
python train_fishfarm_nav.py --total-steps 300000 --cbf     # -> fishfarm_nav.npz
```
Pass the result to the demo with `--nav-policy fishfarm_nav.npz`.
